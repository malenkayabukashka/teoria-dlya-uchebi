# Введение в Python: управление пакетами и виртуальная среда

## Философия виртуальных окружений (Virtual Environment)

Виртуальное окружение (`venv`) — это изолированная директория, которая содержит собственную копию интерпретатора Python и изолированный каталог для установленных пакетов (`site-packages`).
Главная цель: изоляция зависимостей. Проект А может требовать `requests==2.25`, а Проект Б — `requests==2.31`. Без venv они бы конфликтовали в глобальной системе.

**Как Python понимает, что он внутри venv?**

Когда ты активируешь окружение (например, командой `source venv_name/bin/activate` в `bash/zsh`), скрипт активации делает две ключевые вещи:

1. Изменяет переменную окружения `PATH`, добавляя путь к `bin` директории виртуального окружения в самое начало. Поэтому команда `python` вызывает именно локальный интерпретатор.
2. Создает специальную переменную окружения `VIRTUAL_ENV`, значением которой является абсолютный путь к корневой папке этого виртуального окружения.

**Модуль `os` и работа с переменными окружения**

В задании явно указано: *Разрешенные функции: import os.*
Модуль `os` предоставляет словарь `os.environ`, который содержит все переменные окружения текущего процесса.

* Обращение по ключу: `os.environ['VIRTUAL_ENV']`. Если ключа нет (окружение деактивировано), это вызовет исключение `KeyError`.
* Безопасное получение: `os.environ.get('VIRTUAL_ENV')`. Если ключа нет, вернет `None` (или значение по умолчанию, если указать вторым аргументом).
