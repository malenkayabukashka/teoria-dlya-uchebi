# Введение в Python: управление пакетами и виртуальная среда

## Философия виртуальных окружений (Virtual Environment)

Виртуальное окружение (`venv`) — это изолированная директория, которая содержит собственную копию интерпретатора Python и изолированный каталог для установленных пакетов (`site-packages`).
Главная цель: изоляция зависимостей. Проект А может требовать `requests==2.25`, а Проект Б — `requests==2.31`. Без venv они бы конфликтовали в глобальной системе.

**Как Python понимает, что он внутри venv?**

Когда ты активируешь окружение (например, командой `source venv_name/bin/activate` в `bash/zsh`), скрипт активации делает две ключевые вещи:

1. Изменяет переменную окружения `PATH`, добавляя путь к `bin` директории виртуального окружения в самое начало. Поэтому команда `python` вызывает именно локальный интерпретатор.
2. Создает специальную переменную окружения `VIRTUAL_ENV`, значением которой является абсолютный путь к корневой папке этого виртуального окружения.

**Модуль `os` и работа с переменными окружения**

В задании явно указано: *Разрешенные функции: import os.*
Модуль `os` предоставляет словарь `os.environ`, который содержит все переменные окружения текущего процесса.

* Обращение по ключу: `os.environ['VIRTUAL_ENV']`. Если ключа нет (окружение деактивировано), это вызовет исключение `KeyError`.
* Безопасное получение: `os.environ.get('VIRTUAL_ENV')`. Если ключа нет, вернет `None` (или значение по умолчанию, если указать вторым аргументом).

## Создание виртуального окружения**

`python3 -m venv <твой_никнейм>`

* Флаг `-m` говорит Python запустить библиотеку как скрипт. В данном случае это встроенный модуль venv.
* Python создает новую папку с именем твоего никнейма.
* Внутри этой папки создается изолированная структура: `bin/` (или `Scripts`/ на Windows) с копией интерпретатора Python и утилитой `pip`, а также папка `lib/` для будущих пакетов.
* Важно: В этой папке нет переменной окружения. Она создается только при активации.

## Механика активации (source)

Когда ты пишешь `source <твой_никнейм>/bin/activate`, происходит магия на уровне оболочки `(bash/zsh)`:

1. Скрипт `activate` находит путь к директории, в которой он находится, и запоминает его.
2. Он добавляет переменную окружения `VIRTUAL_ENV`, присваивая ей этот абсолютный путь.
3. Он модифицирует системную переменную `PATH`, помещая путь к `bin` виртуального окружения в самое начало. Теперь, когда ты пишешь python или python3, система находит его в `venv`, а не в `/usr/bin/`.

На Windows структура виртуального окружения отличается от macOS/Linux. Вместо папки `bin` используется папка `Scripts`.

`source tameikaf/Scripts/activate`

## Менеджер пакетов `pip`

`pip` — это стандартный установщик пакетов для Python. Поскольку ты находишься внутри активированного виртуального окружения, команда `pip install` <библиотека> установит библиотеку только в папку `lib/` твоего окружения. Глобальный Python на твоей машине не изменится.

## Библиотека `termgraph`

Это утилита, которая рисует простые графики (столбчатые, линейные) прямо в терминале, используя Unicode-символы.

**Важно:** `termgraph` — это не Python-библиотека, которую ты импортируешь через `import termgraph`. Это консольная утилита. После установки через `pip` в папке `tameikaf/Scripts/` (или `bin/` на Linux) появится исполняемый файл `termgraph`, который можно вызывать прямо из терминала.

**Формат данных для `termgraph`**

`termgraph` читает данные из обычного текстового файла. Самый простой и надежный формат — `CSV` (через запятую) или `TSV` (через табуляцию).

Пример структуры файла `data.dat`:
```text
2020, 100
2021, 200
2022, 150

@ Название1,Название2,Название3
Метка1, Значение1_1, Значение1_2, Значение1_3
Метка2, Значение2_1, Значение2_2, Значение2_3
```
Где первый столбец — это подписи (ось X), а второй — значения (ось Y).

**Синтаксис цветов в termgraph**

*Вариант А* (через слэш): --color {cyan/red}

*Вариант Б* (через кавычки): --color "cyan red"

Валидные цвета: `red, green, blue, yellow, magenta, cyan, black, white`.

**Аргументы командной строки для termgraph**

* --color — включает цветовую схему (голубой для первой серии, красный для второй).
* --title "Название" — добавляет заголовок (если нужен).
* --width N — задает максимальную ширину графика в символах (опционально).
* --stacked — если бы нужно было накладывать полосы друг на друга (в твоем случае — нет, они идут рядом).

## Библиотека `subprocess` — запуск внешних команд из Python

`subprocess` — это встроенный модуль Python, который позволяет запускать другие программы и команды терминала прямо из твоего Python-кода. Представь, что ты пишешь скрипт, который должен вызвать `git`, `pip`, `ls` или любую другую системную команду — subprocess делает это возможным.

**Основные функции**

1. `subprocess.run()` — самая универсальная (используется в 90% случаев)
Запускает команду, ждёт её завершения и возвращает объект `CompletedProcess` с результатами.
```python
import subprocess

# Простейший вызов
result = subprocess.run(['ls', '-la'])
```

2. 
| Параметр | Что делает | Пример |
|--|--|--|
| args | Список аргументов команды | ['pip', 'install', 'requests'] 
| capture_output=True | Захватывает stdout и stderr (иначе вывод идёт сразу в терминал) | result.stdout будет содержать текст 
| text=True | Возвращает вывод как строку, а не как байты | Без этого пришлось бы делать .decode('utf-8') 
| check=True | Выбрасывает CalledProcessError, если команда завершилась с ошибкой (код возврата ≠ 0) | Fail-fast подход |
| cwd='путь' | Запускает команду в указанной директории | cwd='/home/user/project' |
| env={...} | Передаёт свой набор переменных окружения | Для изоляции |

```python
result = subprocess.run(['pip', 'freeze'], capture_output=True, text=True)
all_packages = result.stdout  # строка со списком пакетов
```

2. `subprocess.check_output()` — упрощённая версия
3. 
Возвращает только stdout (без объекта `CompletedProcess`). Удобно, когда нужен только вывод.

```python
output = subprocess.check_output(['pip', 'freeze'], text=True)
```
⚠️ Если команда завершится с ошибкой — выбросит исключение автоматически (встроенный `check=True`).

3. `subprocess.Popen()` — для продвинутых случаев

Запускает процесс асинхронно (не ждёт завершения). Нужно, когда ты хочешь:

* Читать вывод построчно в реальном времени
* Отправлять данные в stdin процесса
* Управлять долгоживущими процессами

```python
process = subprocess.Popen(['ping', 'google.com'], stdout=subprocess.PIPE, text=True)
for line in process.stdout:
    print(line, end='')
```
Для школьных заданий обычно хватает `subprocess.run()`.

**Почему список, а не строка?**
```python
# ✅ Правильно (безопасно):
subprocess.run(['ls', '-la', 'my folder'])

# ⚠️ Опасно (если имя папки содержит пробелы или спецсимволы):
subprocess.run('ls -la my folder', shell=True)  # shell=True — избегай без необходимости
```
Когда передаёшь список, Python сам корректно экранирует аргументы. `shell=True` может привести к уязвимостям (command injection), если в аргументах есть пользовательский ввод.
Коды возврата:
* `0` — успех
* `1` и выше — ошибка
* Проверить: `result.returncode == 0`

## Библиотека `shutil` — высокоуровневые операции с файлами

`shutil (shell utilities)` — встроенный модуль для копирования, перемещения, удаления файлов и папок, а также работы с архивами. Это то, что ты обычно делаешь в файловом менеджере, но из кода.

**1. Работа с архивами (то, что мы использовали)**
```python
import shutil

# Создать архив
shutil.make_archive('имя_архива', 'формат', 'папка_для_архивации')
```
Поддерживаемые форматы: `'zip'`, `'tar'`, `'gztar'`, `'bztar'`, `'xztar'`
```python
# Примеры:
shutil.make_archive('backup', 'zip', 'my_folder')       # backup.zip
shutil.make_archive('backup', 'tar', 'my_folder')       # backup.tar
shutil.make_archive('backup', 'gztar', 'my_folder')     # backup.tar.gz
```
⚠️ Важно: `make_archive` создаёт архив в текущей рабочей директории (откуда запущен скрипт), а не рядом с исходной папкой. Если нужно в конкретное место — используй параметр `root_dir` или меняй `cwd`.

Распаковка архива:
```python
shutil.unpack_archive('backup.zip', 'куда_распаковать')
```

**2. Копирование файлов и папок**
```python
# Копировать файл
shutil.copy('source.txt', 'destination.txt')
shutil.copy2('source.txt', 'dest/')  # сохраняет метаданные (даты)

# Копировать папку целиком
shutil.copytree('source_folder', 'destination_folder')
```

**3. Перемещение**
```python
shutil.move('old_path/file.txt', 'new_path/file.txt')
```

**4. Удаление**
```python
shutil.rmtree('папка')  # удаляет папку со всем содержимым (аналог rm -rf)
```
⚠️ Осторожно: `rmtree` не спрашивает подтверждения. Использовать с осторожностью!

**5. Полезные утилиты**
```python
shutil.which('python')      # найти путь к исполняемому файлу в PATH
shutil.disk_usage('/')      # информация о диске
shutil.get_terminal_size()  # размер терминала
```

## Профилирование кода

**Профилирование** — это измерение производительности кода: сколько времени выполняется функция, сколько раз она вызывается, где "узкие места". В отличие от простого time.time(), профилировщик даёт детальную статистику.

**1. `cProfile` — встроенный профилировщик**

Стандартный инструмент Python. Даёт таблицу с количеством вызовов, общим и средним временем каждой функции.
```python
import cProfile

# Способ 1: из кода
cProfile.run('my_function()')

# Способ 2: из терминала
# python -m cProfile -o output.prof my_script.py
```
Ключевые колонки вывода:

* `ncalls` — сколько раз вызвана функция
* `tottime` — общее время внутри функции (без учёта вызовов других функций)
* `cumtime` — кумулятивное время (включая вызовы других функций)
* `filename:lineno(function)` — где функция определена

**2. `time` — простое измерение времени**
```python
import time

start = time.perf_counter()  # более точный, чем time.time()
# ... код ...
end = time.perf_counter()
print(f"Выполнено за {end - start:.4f} секунд")
```

**3. `timeit` — для микро-бенчмарков**
```python
import timeit
timeit.timeit('"-".join(str(n) for n in range(100))', number=10000)
```

## Парсинг

(от англ. parsing — разбор, структурирование) — это автоматизированный процесс сбора, извлечения и систематизации информации из различных источников с помощью специальных программ — парсеров. Проще говоря, это технология, которая позволяет машине «читать» цифровые документы так же, как человек, но в тысячи раз быстрее.

1. **Получение данных.** Парсер подключается к источнику: отправляет HTTP-запрос для веб-страницы и получает её HTML-код, обращается к API для получения структурированных данных (в формате JSON или XML) или читает локальный файл (XML, CSV, Excel).

2.**Извлечение информации.** Парсер анализирует структуру данных и находит нужные элементы. Для этого могут использоваться: 

* `XPath` и `CSS-селекторы` — специальные языки запросов для точного выбора элементов в HTML-коде. 
* Регулярные выражения — для поиска неструктурированного текста. 

3. **Очистка и нормализация.** Извлечённые данные часто содержат «мусор» (лишние пробелы, HTML-теги, скрытые символы). Парсер удаляет его, приводит даты и числа к единому формату, убирает дубликаты.

4. **Сохранение.** Результат сохраняется в удобном для дальнейшей работы виде: в таблицу (Excel, Google Sheets), базу данных или файл (CSV, JSON). Многие парсеры можно настроить на регулярный запуск по расписанию.

### Виды парсинга**

* **HTML-парсинг**. Извлечение данных из HTML-разметки веб-страниц. Подходит для сбора информации с карточек товаров, описаний услуг, таблиц.
* **API-парсинг.** Если сайт предоставляет API, парсер подключается к нему и получает структурированные данные напрямую. Это часто более стабильный и быстрый способ.
* **Скрин-сбор** (Screen scraping). Парсер анализирует не код страницы, а её визуальное отображение, как его видит пользователь. Используется браузерная автоматизация или распознавание текста на изображениях. Этот метод полезен для сайтов с динамически подгружаемым контентом или сложной вёрсткой, но работает медленнее и требует больше ресурсов.
* **Парсинг файлов.** Обработка уже готовых файлов (XML, CSV, JSON, Excel) без обращения к веб-страницам.

1. Как получить HTML-страницу (requests)

Чтобы спарсить сайт, его сначала нужно скачать. Для этого используется библиотека requests.
```python
import requests

response = requests.get('https://finance.yahoo.com/quote/MSFT/financials/')
html_content = response.text
```

⚠️ Важный нюанс (Ловушка Yahoo Finance): Yahoo Finance блокирует запросы от стандартных Python-скриптов (возвращает ошибку 403 Forbidden). Чтобы обмануть сайт и притвориться обычным браузером, нужно передать заголовок User-Agent:
```python
headers = {'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64)'}
response = requests.get(url, headers=headers)
```

2. Как разобрать HTML `(BeautifulSoup)`

`requests` скачивает "сырой" текст. `BeautifulSoup` превращает его в дерево объектов, по которому удобно искать.
```python
from bs4 import BeautifulSoup

soup = BeautifulSoup(html_content, 'html.parser')
# Найти все строки таблицы
rows = soup.find_all('tr')
```

3. Аргументы командной строки (sys.argv)

Чтобы скрипт принимал тикер и поле при запуске (`./financial.py 'MSFT' 'Total Revenue'`), мы используем модуль `sys`.
```python
import sys

ticker = sys.argv[1]   # 'MSFT'
field = sys.argv[2]    # 'Total Revenue'
```

 Это нужно, чтобы не спамить запросами к серверу Yahoo (иначе они забанят твой IP).
