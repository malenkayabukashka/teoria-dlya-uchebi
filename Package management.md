# Введение в Python: управление пакетами и виртуальная среда

## Философия виртуальных окружений (Virtual Environment)

Виртуальное окружение (`venv`) — это изолированная директория, которая содержит собственную копию интерпретатора Python и изолированный каталог для установленных пакетов (`site-packages`).
Главная цель: изоляция зависимостей. Проект А может требовать `requests==2.25`, а Проект Б — `requests==2.31`. Без venv они бы конфликтовали в глобальной системе.

**Как Python понимает, что он внутри venv?**

Когда ты активируешь окружение (например, командой `source venv_name/bin/activate` в `bash/zsh`), скрипт активации делает две ключевые вещи:

1. Изменяет переменную окружения `PATH`, добавляя путь к `bin` директории виртуального окружения в самое начало. Поэтому команда `python` вызывает именно локальный интерпретатор.
2. Создает специальную переменную окружения `VIRTUAL_ENV`, значением которой является абсолютный путь к корневой папке этого виртуального окружения.

**Модуль `os` и работа с переменными окружения**

В задании явно указано: *Разрешенные функции: import os.*
Модуль `os` предоставляет словарь `os.environ`, который содержит все переменные окружения текущего процесса.

* Обращение по ключу: `os.environ['VIRTUAL_ENV']`. Если ключа нет (окружение деактивировано), это вызовет исключение `KeyError`.
* Безопасное получение: `os.environ.get('VIRTUAL_ENV')`. Если ключа нет, вернет `None` (или значение по умолчанию, если указать вторым аргументом).

## Создание виртуального окружения**

`python3 -m venv <твой_никнейм>`

* Флаг `-m` говорит Python запустить библиотеку как скрипт. В данном случае это встроенный модуль venv.
* Python создает новую папку с именем твоего никнейма.
* Внутри этой папки создается изолированная структура: `bin/` (или `Scripts`/ на Windows) с копией интерпретатора Python и утилитой `pip`, а также папка `lib/` для будущих пакетов.
* Важно: В этой папке нет переменной окружения. Она создается только при активации.

## Механика активации (source)

Когда ты пишешь `source <твой_никнейм>/bin/activate`, происходит магия на уровне оболочки `(bash/zsh)`:

1. Скрипт `activate` находит путь к директории, в которой он находится, и запоминает его.
2. Он добавляет переменную окружения `VIRTUAL_ENV`, присваивая ей этот абсолютный путь.
3. Он модифицирует системную переменную `PATH`, помещая путь к `bin` виртуального окружения в самое начало. Теперь, когда ты пишешь python или python3, система находит его в `venv`, а не в `/usr/bin/`.

На Windows структура виртуального окружения отличается от macOS/Linux. Вместо папки `bin` используется папка `Scripts`.

`source tameikaf/Scripts/activate`

## Менеджер пакетов `pip`

`pip` — это стандартный установщик пакетов для Python. Поскольку ты находишься внутри активированного виртуального окружения, команда `pip install` <библиотека> установит библиотеку только в папку `lib/` твоего окружения. Глобальный Python на твоей машине не изменится.

## Библиотека `termgraph`

Это утилита, которая рисует простые графики (столбчатые, линейные) прямо в терминале, используя Unicode-символы.

**Важно:** `termgraph` — это не Python-библиотека, которую ты импортируешь через `import termgraph`. Это консольная утилита. После установки через `pip` в папке `tameikaf/Scripts/` (или `bin/` на Linux) появится исполняемый файл `termgraph`, который можно вызывать прямо из терминала.

**Формат данных для `termgraph`**

`termgraph` читает данные из обычного текстового файла. Самый простой и надежный формат — `CSV` (через запятую) или `TSV` (через табуляцию).

Пример структуры файла `data.dat`:
```text
2020, 100
2021, 200
2022, 150
```
Где первый столбец — это подписи (ось X), а второй — значения (ось Y).
